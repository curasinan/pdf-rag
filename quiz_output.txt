**Question 2 — Stack Frame & Calling Conventions (Conceptual Understanding)**
*Source: L17_x86_Stack-1, pages 13-16; L18_x86_CallingConventions, pages 24-26; CS 220 Notes on Stack Layout*

During a function's **preamble**, the following two instructions execute:

```asm
pushq  %rbp
movq   %rsp, %rbp
```

Explain **what each instruction accomplishes** and **why** this sequence is necessary before the function can use its own stack frame.

**Question 3 — Addressing Modes & Array Access (Application)**
*Source: L15_x86_Instructions, pages 1-17; Practice Exam 2, Q1*

Suppose `%rax = 0x7fffffffe750`, pointing to the first element of the `int` array `{2, -1, 10, 12, -30}`. The following code executes:

```asm
xor %rdx, %rdx
mov (%rax), %edx
mov (%rax,%rdx,4), %ecx
```

(a) What value ends up in `%edx`?
(b) What value ends up in `%ecx`?
(c) What is the difference between `mov` and `lea` when used with the same memory operand `(%rax,%rdx,4)`?

**Question 4 — Caller-Saved vs. Callee-Saved Registers (Comparison)**

(a) If function `foo` needs to use `%rbx`, what must `foo` do before and after using it?
(b) If `main` has an important value in `%rdi` and is about to `call foo`, what must `main` do to preserve it?
(c) Which of the first six parameter registers (`%rdi`, `%rsi`, `%rdx`, `%rcx`, `%r8`, `%r9`) are caller-saved or callee-saved?

**Question 5 — Buffer Overflow Attacks (Application & Analysis)**
*Source: L19_Buffer_Overflow_Attack, pages 11-30*

A function `getString()` declares `char buffer[96]` and calls `gets(buffer)`. The saved `%rbp` is at `buffer + 96` and the return address is at `buffer + 104`.

(a) Explain step-by-step how an attacker can redirect execution to an arbitrary address using this vulnerability.
(b) Name **three** prevention techniques discussed in class and briefly explain how each one works.
(c) Why must the binary data in the overflow payload **not** contain the byte `0x0A`?

# Answer Key

**Q1:** **Carry** and **Zero** are set.
- Result = `0xFF + 0x01 = 0x100`, truncated to `0x00` in 8 bits.
- **CF = 1**: there is a carry out of the most significant bit.
- **ZF = 1**: the result is all zeros.
- **SF = 0**: the high bit of the result (`0x00`) is 0.
- **OF = 0**: operands are opposite sign (negative + positive), so signed overflow cannot occur.

**Q2:**
- `pushq %rbp` saves the **caller's base pointer** onto the stack (decrements `%rsp` by 8 and writes the old `%rbp` value). This preserves the caller's frame so it can be restored on return.
- `movq %rsp, %rbp` sets `%rbp` to the current top of stack, establishing the **base of the new stack frame**. All local variables and parameters will be accessed as negative offsets from this `%rbp`.
- This sequence is necessary because each function needs its own frame pointer to reference its locals, and the caller's frame must be recoverable when the function returns (via `popq %rbp` or `leave`).

**Q3:**
(a) `%edx = 2` (the first element of the array, loaded from `(%rax)`).
(b) `%ecx = 10`. The address is `%rax + %rdx*4 = base + 2*4 = base + 8`, which is `array[2] = 10`.
(c) `mov` **dereferences** the computed address and loads the value from memory. `lea` computes the same address but stores the **address itself** into the destination register without accessing memory.

**Q4:**
(a) `foo` must `pushq %rbx` in its preamble and `popq %rbx` before returning, restoring the caller's value.
(b) `main` must `pushq %rdi` before the `call` and `popq %rdi` afterward, since `foo` is free to overwrite `%rdi`.
(c) All six parameter registers (`%rdi`, `%rsi`, `%rdx`, `%rcx`, `%r8`, `%r9`) are **caller-saved** (volatile). The callee may freely modify them.

**Q5:**
(a) The attacker provides input longer than 96 bytes. The first 96 bytes fill `buffer`. The next 8 bytes overwrite the saved `%rbp`. The following 8 bytes overwrite the **return address**. When `getString` executes `ret`, it pops the attacker-controlled address into `%rip`, redirecting execution to arbitrary code. The attacker must write these bytes in **little-endian** order.
(b) Three prevention techniques:
1. **Use `fgets` instead of `gets`** — limits the number of bytes read, preventing the buffer from being overrun.
2. **ASLR (Address Space Layout Randomization)** — randomizes where code is loaded in memory each run, so the attacker cannot predict the target address to jump to.
3. **Memory protection (NX/DEP)** — stack pages are marked non-executable, so even if the attacker injects code into the buffer, the CPU will fault when trying to execute it. (Stack guards / `-fstack-protector` is also acceptable.)
(c) `gets()` reads until it encounters a newline character (`\n`), which is `0x0A` in ASCII. If `0x0A` appears in the payload, `gets` will interpret it as the end of input and stop reading, truncating the attack payload before the return address is overwritten.
